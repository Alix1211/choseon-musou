# GPT 작업 지침 — 삼국 초선 무쌍 "가벼운 스테이지 규칙" (브랜치 `gpt-gimmicks`)

이 문서를 **끝까지** 읽고 시작하세요. 먼저 `HANDOVER.md` §1(케인 작업 규칙)과 §3(빌드 구조), §10(최근 변경)도 읽으세요.
케인(이관우)은 프로그래머가 아닙니다. 케인과의 대화는 **한국어 존댓말(격식체), 기술 설명 최소화, 결과물과 케인이 할 일만** 전달합니다.

## 0. 맡은 일
`docs/STAGE_PLAN.md` 표에서 담당이 **GPT**인 판(2·4·7·8·9·12·13·16·19·23·24·25·31·32·34)의 규칙을 만듭니다.
규칙의 종류는 표 그대로입니다(감시탑 점령, 보급창 방화, 복병, 비밀 문, 막힌 길 돌아가기, 스위치, 일기토, 내응자, 전령 추격, 제단 파괴).
화계·수공·미인계·호위·미로·시간 버티기처럼 **새 시스템이 필요한 것은 Claude 담당**이니 건드리지 마세요. 필요하면 케인에게 먼저 묻습니다.
APK 빌드, 소리, 진동도 하지 않습니다.

## 1. 지켜야 할 규칙 (어기면 작업이 사라지거나 케인이 화냅니다)
1. **`index.html`을 직접 고치지 마세요.** 이 파일은 `python3 _new/p2.py`가 만드는 결과물이라 다음 빌드에 수정이 사라집니다. `index.v1.html`(방치형 원본)도 절대 고치지 않습니다.
2. 이 브랜치(`gpt-gimmicks`)에서만 작업하고 **`main`에는 올리지 않습니다.** 좋으면 케인이 Claude에게 합치라고 합니다.
3. **케인이 준 대사·원고는 한 글자도 고치지 않습니다**(`script.md`, `m3_dlg.js`, `KAN_TALK`, `LOSS` 등). 새 안내 문구는 짧게, 기존 톤을 따릅니다.
4. 쓸 수 없는 버튼은 반드시 **비활성(회색)** 으로 둡니다. 시작·종료 화면에 안내 문구를 늘리지 않습니다.
5. 한 번에 **한 판씩** 만들고, 판마다 빌드와 시험을 통과한 뒤 커밋합니다. 여러 판을 섞어 고치지 않습니다.
6. 스테이지별 나라(`stageSet`), 오오라 제거, 적 능력치, 벽 우회(`chaseMove`)는 건드리지 않습니다.
7. Claude가 `main`에서 `_new/p2e.py`, `m3_gen.js`, `m3_mis.js`를 계속 고칠 수 있으니, **기존 파일은 꼭 필요한 한두 줄만** 고치고 나머지는 새 파일에 씁니다(합칠 때 충돌을 줄이기 위함).

## 2. 어디에 코드를 넣나
- 새 규칙 코드는 **`_new/m3_gim.js`**(새 파일)에, 기존 코드에 끼우는 부분은 **`_new/p2g.py`**(새 파일)에 씁니다.
- `_new/p2.py` 끝, `p2e.py`를 실행하는 줄 **바로 뒤**에 한 줄만 추가합니다:
  `if not os.environ.get('NOD'):exec(open(B+'_new/p2g.py',encoding='utf-8').read())`
- `p2g.py` 안에서는 `rep(old, new, cnt=1)`(정확한 문자열 치환, 횟수를 맞추지 못하면 빌드가 멈춤)와 `rd('m3_gim.js')`(새 파일 읽기)를 쓸 수 있습니다. 예: `rep("function updateMob(m,dt){", rd('m3_gim.js')+"\nfunction updateMob(m,dt){")` — `p2e.py`가 이미 비슷한 방식을 쓰니 참고하세요(`p2e.py`를 읽어 보세요).
- 디버그용 `window.G`에 새 함수를 노출하려면 `rep("openExit,KAN_PLAN};","openExit,KAN_PLAN,내함수};")` 식으로 추가합니다(`p2.py`의 `G` 정의 끝부분).
- 빌드: `python3 _new/p2.py` → `ok 숫자`가 나오면 정상. 시험 서버: `python3 srv.py`(포트 8766).

## 3. 이미 있는 장치 (코드로 확인된 것만)
- **판별 규칙 이름표:** `m3_lay.js`의 `GIM_OF={1:'commander',3:'vents'}`. 판 번호 → 규칙 키. 새 규칙 키를 여기에 추가하거나, 덮어쓰는 방식으로 연결합니다.
- **규칙이 맵에 들어가는 곳:** `m3_gen.js`의 칸 생성 부분(`gim==='commander'`와 3판 독 연기). 1판 거점병장이 가장 단순한 예이니 **먼저 읽고 같은 방식으로** 만드세요.
- **군락 만들기:** `mkCol(tx,ty,{n,leader,commander,guard,captain,hold,tag,set})`.
- **미션 상태:** `M.mis` ∈ `cmd | guard | exit | inner | hero | rescue | done`. 문구는 `misText()`, 화살표 목표는 `misTarget()`(둘 다 `m3_mis.js`). 새 규칙은 보통 `M.mis`에 새 값을 더하고 이 두 함수에 한 줄씩 추가합니다.
- **문 열기:** `openExit()`(다음 칸 출구), `openGate(id)`(내성문 등). 대장·수문장이 쓰러지면 `onBeaconDead`, `onGuardDead`, `onCaptainDead`가 부릅니다.
- **칸 이동·상시 처리:** `goNext()`, `missionTick(dt)`. 시간제 규칙은 `missionTick`에서 처리합니다.
- **지형:** `M.D.g[y][x]` 1=걸을 수 있음 0=막힘, 한 칸 `TS=48`px. `blockedAt(px,py,r)`가 실제 충돌 판정. 비밀 문(벽 한 칸을 1로 바꾸기)을 만들 때 **통로 폭이 2칸 이상**이어야 초선(반경 18)이 지나갑니다(`m3_lay.js`의 `wide`/`wideRooms`, 시험 `t_wide.js`·`t_real.js`).
- **항아리·상자:** `breakJars(rad)`, `openChest(p)`. 비밀 문을 항아리로 여는 규칙은 `M.jarList`를 확인하세요.

## 4. 시험 (매 판 필수)
1. `node t_flow.js 판번호` — 칸 흐름(처치→문 열림→이동). **초선이 1레벨이라 높은 판은 적에게 먼저 쓰러져 실패할 수 있습니다**(옛 빌드도 같음). 높은 판은 초선 체력을 계속 채우거나 레벨을 올려서 시험하세요(방법은 직접 확인).
2. `node t_wall.js index.html` — 벽 우회 시험(계속 통과해야 함).
3. 맵을 건드렸다면 `t_all.js`, `t_real.js`, `t_wide.js`(도달성, 불량 0이어야 함).
4. 새 규칙마다 **자기 시험**(예: `t_gim_02.js`)을 만들어 "규칙 조건을 채우면 문이 열린다 / 못 채우면 안 열린다"를 확인합니다.
5. Playwright 실행: `NODE_PATH=$(npm root -g) node 파일.js`. 칸 도착 대사가 뜨면 `[data-a="dskip"]`를 눌러 넘깁니다.
6. 화면을 스크린샷으로 확인하고, 케인에게는 "무엇을 어떻게 해야 문이 열리는지" 한두 문장으로 전합니다.
