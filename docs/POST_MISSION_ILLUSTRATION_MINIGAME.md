# 미션 종료 후 일러스트 · 리듬 미니게임 (사용자 결정 사항)
> 기록일: 2026-10-30 · 브랜치 `gpt-gimmicks` · **기획/음원 보관 단계, 신규 미니게임 미구현**

## 1. 확정된 요구사항

1. **어떤 미션이든 승리하여 완료하면** 구출/포획/일반/진입/최종전 구분 없이 플레이어가 보유한 일러스트 중 **무작위 한 장**을 띄운다. 이미 완료한 미션을 다시 클리어해도 동일하다. 패배, 철수에는 적용하지 않는다.
2. 게임에서 **플레이어가 일러스트 폴더를 직접 지정**한다. 그 폴더뿐 아니라 **모든 깊이의 하위 폴더**에 있는 이미지도 포함한다. 임의의 고정된 디렉터리로 제한하지 않는다.
3. 일러스트 화면에 결합할 **후속 미니게임용 BPM별 음악은 90 / 120 / 150 BPM 세 트랙**이다. 구체적인 미니게임 조작법, 난이도 및 BPM 선택 조건은 **아직 미결정**이므로 임의로 구현하거나 결정하지 않는다.
4. 기존 일러스트·원본 이미지와 제공한 음원은 임의 편집/삭제/재생성하지 않는다. 사용자가 직접 지정한 폴더 및 파일을 임의 업로드하거나 GitHub에 포함하지 않는다.

## 2. 현재 게임 코드와 필요한 보강

현재 `index.html`의 `endStage()`는 미션 성공 시 스토리 종료 대화 뒤 `showCut(r,()=>showResult(r))`를 실행한다. `pickCut()`는 `UI.cutFiles`에서 한 장을 무작위로 고르며 없으면 기본 컷을 사용한다. 그래서 **승리 후 랜덤 컷의 기본 연결은 이미 존재**한다.

현재 폴더 선택 `<input type="file" id="cutdir" webkitdirectory multiple>` 및 `cutdir` 이벤트는 브라우저가 전달하는 파일을 한 세션에서 목록화한다. 일부 Android WebView의 폴더 선택 UI, 깊은 하위 폴더 접근, 재실행 후 선택 유지 여부는 검증되지 않았다. 단일 기본 컷은 IndexedDB에 저장되지만 선택한 폴더 전체는 그렇지 않다.

**향후 Android 구현 요구:**
- Android Storage Access Framework의 `ACTION_OPEN_DOCUMENT_TREE` 등 적절한 폴더 선택 수단 검토. 가능한 Android 버전에서는 사용자가 선택한 트리 URI에 `takePersistableUriPermission`을 적용하고 선택 정보를 로컬에 유지.
- `DocumentFile` 기반 **재귀 순회**로 하위 폴더 이미지 포함. 지원 형식(JPG/PNG/WebP 등)만 수집; 디코딩 불가능한 이미지는 건너뛴다.
- 플레이어의 지역 파일이므로 사용자가 지정한 폴더 밖을 탐색하지 않음. 로컬 URI를 원격 서버/저장소로 전송하지 않음.
- 폴더 미지정·빈 폴더·권한 해제·원본 이동 시 기존 기본 컷으로 안전하게 복귀. UI에는 이미지 수, 폴더 변경/해제, 무작위 미리보기 표시.
- 무작위 선택은 해당 클리어마다 한 장을 뽑되, 미리보기/실제 화면을 넘기는 과정에서 갑자기 다른 이미지로 바뀌지 않도록 한다.
- Android WebView ↔ 네이티브 폴더 선택기의 결과 전달을 검증하고, 실제 태블릿에서 재실행·하위 폴더·대량 이미지 탐색을 테스트한다.

**BPM 값은 사용자가 지정한 음원명에 근거한 분류**다. 게임의 정확한 싱크는 미니게임 설계 시 실제 박자와 시작 오프셋을 측정해 보정한다.

### 음악 적용할 때 주의할 사항
- 미니게임이 시작되면 선택 BPM 트랙을 재생하고 끝나면 중지한다. 다른 BGM과 중복 출력되거나 게임 일시정지 중 계속 재생되지 않도록 오디오 상태 관리.
- 90/120/150 중 어떤 것을 언제 틀지, 속도 전환 및 종료 조건은 사용자 결정 대기.
- 음악이 두 분이더라도 미니게임 자체를 정확히 두 분으로 제한하라는 요구는 없음.
- 파일명만 바꾸고 내용은 재인코딩·편집하지 않는다. `a/audio/`의 기존 타이틀·병영·전투 BGM 및 효과음은 유지.

## 4. 보관 상태와 후속 작업

- **기획 문서 및 음원 매니페스트는 GitHub에 커밋됨.**
- 음원 원본은 이 채팅에 사용자가 업로드했고, 같은 3개 파일을 `Choseon_Minigame_BPM_90_120_150.zip`에 각각 `a/audio/minigame/bpm_*.mp3` 구조로 묶었다.
- **현재 GitHub 연결 도구는 텍스트/깃 Blob 생성은 되지만 이 채팅에 있는 바이너리 첨부 파일을 GitHub로 직접 전송할 수 없으므로, 실제 MP3는 저장소에 아직 없음.** 파일이 저장소에 올라가기 전까지 `manifest.json`의 `repository_uploaded=false`를 유지할 것. 파일 업로드 후 SHA-256 확인하고 상태 갱신.
- 다음 구현에서는 **기존 `showCut` 및 결과 화면 흐름을 우선 재사용**하며, 폴더 선택 기능과 미니게임 로직을 분리해서 개발한다. 사용자가 미니게임 방식 결정 전 임의로 탭/연타/리듬 판정 등을 추가하지 않는다.
